# Sneaker Store — Telegram Mini App

Интернет-магазин кроссовок в виде Telegram Mini App: каталог, корзина, оформление заказа, профиль — и встроенная панель «Управление» для владельца магазина (товары, категории, баннеры, заказы, реквизиты, AI-ассистент).

## Стек

- **Клиент**: React 18 + Vite 5 + Tailwind CSS, React Router v6
- **Сервер**: Node.js + Express 4 (ESM)
- **БД**: PostgreSQL (рекомендуется [Neon](https://neon.tech))
- **Интеграция**: Telegram Web App API + Telegram Bot API (уведомления)

## Структура проекта

```
telegram-mini-shop/
├── client/   # React-приложение (Mini App + встроенная панель «Управление»)
└── server/   # Express API + работа с БД + бот-уведомления
```

## Мультимагазинность

Проект — это платформа: один backend + один деплой клиента обслуживают произвольное число независимых магазинов. Каждый магазин — отдельная строка в таблице `shops`:

```sql
CREATE TABLE shops (
  id SERIAL PRIMARY KEY,
  name VARCHAR(255),
  description TEXT,
  owner_telegram_id BIGINT UNIQUE,
  bot_token VARCHAR(255),
  card_number VARCHAR(50),
  card_holder VARCHAR(100),
  click_number VARCHAR(50),
  currency VARCHAR(10) DEFAULT 'сум',
  is_active BOOLEAN DEFAULT true,
  created_at TIMESTAMP DEFAULT NOW()
);
```

Таблицы `categories`, `products`, `banners`, `orders` ссылаются на магазин через `shop_id`.

**Как клиент определяет магазин.** При открытии Mini App клиент читает `?shop=ID` из URL один раз при старте и передаёт его как `shop_id` во всех запросах к API (`GET /api/products`, `/api/categories`, `/api/banners`, `/api/settings`, `POST /api/orders` и т.д.) — сервер фильтрует данные по этому `shop_id`. Если параметр `?shop=ID` отсутствует, либо магазин с таким `id` не найден или неактивен, вместо приложения показывается заглушка «Магазин не найден».

**Регистрация нового магазина**:

```
POST /api/shops/register
{
  "owner_telegram_id": 123456789,
  "name": "Мой магазин",
  "bot_token": "111:AAA..."   // опционально
}
```

Ответ:

```json
{ "shop_id": 2, "mini_app_url": "https://telegram-mini-shop.netlify.app?shop=2" }
```

`mini_app_url` (формат `<WEBAPP_URL>?shop=<ID>`) — это ссылка, которую нужно указать в @BotFather (Menu Button или `/newapp`) для бота этого магазина; она же отображается в разделе «Управление» → «Реквизиты» с кнопкой копирования. Повторный вызов с тем же `owner_telegram_id` обновит `name`/`bot_token` существующего магазина, не создавая дубликат (за счёт `UNIQUE` на `owner_telegram_id`).

**Управление магазином.** Владелец видит в разделе «Управление» только свои товары/категории/баннеры/заказы/реквизиты — доступ определяется по `Telegram.WebApp.initData` (подпись проверяется токеном бота **этого** магазина — `shops.bot_token`) и сравнением `user.id` с `shops.owner_telegram_id`.

**Демо-магазин.** После `npm run seed` в БД появляется демо-магазин с `id=1` (использует `BOT_TOKEN`/`OWNER_TELEGRAM_ID` из `server/.env`) — открывайте его по адресу `http://localhost:5173/?shop=1`.

## Требования

- Node.js 20+
- База данных PostgreSQL (например, бесплатный проект на Neon)
- Telegram-бот, созданный через [@BotFather](https://t.me/BotFather)

## Настройка сервера

1. Перейдите в папку сервера и установите зависимости:

   ```bash
   cd server
   npm install
   ```

2. Скопируйте `.env.example` в `.env` и заполните значения:

   ```bash
   cp .env.example .env
   ```

   | Переменная | Описание |
   | --- | --- |
   | `BOT_TOKEN` | Токен бота от @BotFather для **демо-магазина (id=1)**, создаваемого через `npm run seed`. Боевые магазины хранят свой токен в таблице `shops` |
   | `DATABASE_URL` | Строка подключения к PostgreSQL (для Neon — со `?sslmode=require`) |
   | `OWNER_TELEGRAM_ID` | Telegram ID (числовой `user.id`) владельца **демо-магазина (id=1)** — на него приходят уведомления о новых заказах, и по нему открывается раздел «Управление» в Mini App |
   | `PORT` | Порт сервера (по умолчанию `3001`) |
   | `WEBAPP_URL` | Публичный URL Mini App без query-параметров (например `https://telegram-mini-shop.netlify.app`). Используется как база для ссылок вида `<WEBAPP_URL>?shop=<ID>` — в ответе `POST /api/shops/register` и в сообщениях бота |

   Платформа — мультимагазинная: проект — это один backend + один деплой клиента, обслуживающие много независимых магазинов. Подробнее см. раздел [«Мультимагазинность»](#мультимагазинность).

3. Создайте таблицы в БД:

   ```bash
   npm run migrate
   ```

4. Заполните демо-данными — создаётся демо-магазин с `id=1` (используя `BOT_TOKEN`/`OWNER_TELEGRAM_ID` из `.env`), 4 категории, 8 товаров, баннеры:

   ```bash
   npm run seed
   ```

5. Запустите сервер в режиме разработки:

   ```bash
   npm run dev
   ```

   Сервер поднимется на `http://localhost:3001` (или на порту из `PORT`).

## Настройка клиента

1. Перейдите в папку клиента и установите зависимости:

   ```bash
   cd client
   npm install
   ```

2. (опционально) Скопируйте `.env.example` в `.env`:

   ```bash
   cp .env.example .env
   ```

   По умолчанию `VITE_API_URL` пуст, и клиент ходит на `/api` — Vite dev-сервер проксирует эти запросы на `http://localhost:3001` (см. `vite.config.js`). Для продакшена укажите полный URL вашего API. Опциональный `VITE_MINI_APP_URL` используется только для отображения ссылки в разделе «Управление» → «Реквизиты».

3. Запустите дев-сервер:

   ```bash
   npm run dev
   ```

   Откройте `http://localhost:5173/?shop=1` в браузере — параметр `?shop=1` указывает на демо-магазин из `npm run seed`. Без `?shop=ID` приложение покажет заглушку «Магазин не найден» (см. [«Мультимагазинность»](#мультимагазинность)). Внутри Telegram (Mini App) `window.Telegram.WebApp` будет доступен автоматически; в обычном браузере приложение тоже работает, но без данных пользователя Telegram.

4. Сборка для продакшена:

   ```bash
   npm run build
   ```

   Статика появится в `client/dist` — её можно раздавать любым статическим хостингом (Vercel, Netlify, Nginx и т.д.).

## Раздел «Управление» (встроенная админка)

Отдельной веб-админки нет — управление магазином встроено прямо в Mini App. Если `user.id`, переданный Telegram Web App, совпадает с `owner_telegram_id` текущего магазина (`shops.owner_telegram_id`, см. [«Мультимагазинность»](#мультимагазинность)), в нижней навигации появляется дополнительная вкладка **«Управление»** (для обычных покупателей она скрыта).

Доступ к API раздела (`/api/admin/*`) защищён на сервере: каждый запрос подписан данными `Telegram.WebApp.initData`, сервер проверяет подпись токеном бота **этого магазина** (`shops.bot_token`) и сверяет `user.id` с `shops.owner_telegram_id`.

Вкладки раздела:

- **Заказы** — список заказов и смена статуса (новый → принят → отправлен → доставлен / отменён)
- **Товары** — добавление/редактирование/удаление, размеры и цвета, количество в наличии по каждому размеру (`sizes_stock`), ссылка на фото с превью, быстрый переключатель наличия
- **Категории** — добавление/удаление, иконки
- **Баннеры** — добавление/удаление баннеров на главной
- **Реквизиты** — название магазина, описание, номер карты, получатель платежа, номер Click
- **AI Ассистент** — подключение Finexia AI (см. ниже)

## Finexia AI

В разделе «Управление» → «AI Ассистент» отображается статус подключения AI-ассистента (по умолчанию «Не подключён») и кнопка **«Подключить»**, которая открывает `https://finexia.uz?ref=miniapp&shop_id=<OWNER_TELEGRAM_ID>` (через `Telegram.WebApp.openLink`, если доступно).

## Telegram-уведомления

- При оформлении нового заказа сервер отправляет сообщение владельцу магазина (`shops.owner_telegram_id`, через бота `shops.bot_token`) с деталями заказа: имя, телефон, адрес, список товаров (название, размер, количество), сумма заказа и две кнопки — **✅ Подтвердить** / **❌ Отменить** (`callback_data`: `confirm_order_<id>` / `cancel_order_<id>`).
  - **✅ Подтвердить** — статус заказа меняется на «Принят», клиенту приходит «Ваш заказ #ID подтверждён! Ожидайте доставку.».
  - **❌ Отменить** — статус меняется на «Отменён», товар (по размеру) возвращается в `sizes_stock`, клиенту приходит уведомление об отмене.
- После оформления заказа покупателю показывается кнопка «Написать продавцу» — она вызывает `Telegram.WebApp.openTelegramLink('https://t.me/<bot_username>?start=order_<id>')`. Бот получает `/start order_<id>`, пересылает владельцу сводку по заказу (товар, размер, цвет, сумма) и просит покупателя отправить туда же фото чека — следующее фото от этого пользователя бот перешлёт владельцу с привязкой к номеру заказа.
- Заказы со статусом «Новый», которые не были подтверждены/отменены в течение **15 минут**, автоматически переводятся в статус «Истёк»: товар возвращается в наличие, клиенту приходит «Ваш заказ #ID отменён — время оплаты истекло.» (фоновая проверка раз в минуту).
- При смене статуса заказа в разделе «Управление» клиенту отправляется уведомление в Telegram через бота того же магазина (если заказ был сделан внутри Mini App и доступен `telegram_user_id`).

Для работы уведомлений у магазина должен быть заполнен `bot_token` (для демо-магазина id=1 — `BOT_TOKEN`/`OWNER_TELEGRAM_ID` в `server/.env`).

### Боты магазинов (long polling)

Сообщения и кнопки (`/start`, `/start order_<id>`, «✅ Подтвердить» / «❌ Отменить», AI-ассистент, фото товара от владельца) обрабатываются через **long polling** — для каждого магазина с заполненным `bot_token` (и `is_active = true`) сервер при старте автоматически создаёт отдельный экземпляр бота (`server/src/services/botManager.js`). Никакой ручной настройки `setWebhook` не требуется.

При вызове `POST /api/shops/register` бот нового (или обновлённого) магазина запускается сразу же, без перезапуска сервера.

## Подключение как Telegram Mini App

Для каждого магазина нужен свой Telegram-бот. Шаги ниже выполняются один раз для платформы (1–2) и затем повторяются для каждого нового магазина (3–5):

1. Разверните `server` (API) и `client` (статика после `npm run build`) на публичных HTTPS-адресах.
2. В `server/.env` укажите `WEBAPP_URL` — публичный URL клиента (без query-параметров).
3. Создайте бота через [@BotFather](https://t.me/BotFather) и получите его токен.
4. Зарегистрируйте магазин — `POST /api/shops/register` с `owner_telegram_id` (Telegram ID владельца), `name` и `bot_token` (см. [«Мультимагазинность»](#мультимагазинность)). В ответе придёт `mini_app_url` вида `<WEBAPP_URL>?shop=<ID>`.
5. В @BotFather для созданного бота: `/mybots` → выберите бота → **Bot Settings** → **Menu Button** → **Configure Menu Button** → укажите `mini_app_url` и текст кнопки (например, «Открыть магазин»). Либо используйте `/newapp` для создания полноценного Mini App, привязанного к боту.
6. После этого кнопка меню бота будет открывать Mini App именно с этим `shop_id`, и владелец будет видеть в разделе «Управление» только свой магазин.

## Полезно знать

- На каждой странице есть подпись внизу: «Powered by Finexia · @finexia_uz».
- Цены отображаются в сумах (UZS), формат настраивается в `server/src/constants.js` и `client/src/utils/format.js`.
- Корзина хранится в `localStorage` браузера и сохраняется между сессиями.
